Petrel Agent MCP

Explicit tools for project inspection, export, audit and selected round-trip experiments, with the evidence and limits returned alongside results.

A controlled route into desktop geoscience

The public MCP server exposes 41 tools without depending on the Ocean SDK. Its documented toolbox includes 32 tools that work on project or export files without launching Petrel. Other routes call saved Petrel workflows or use bounded GUI procedures when required.

The engineering aim is to make each operation inspectable: explicit inputs, validation artifacts, checksums and a result audit. Tools that can launch Petrel default to dry runs and require explicit execution. Unresolved layouts or failed preflights return their limits instead of guessing.

What the evidence covers

The recorded evidence is for Petrel 2018.2 using an automation copy of a Petrel 2010 demo project. The public documentation includes one end-to-end demo-project validation and an 84-row Well Tops ASCII route. New versions, projects and live-application routes require their own setup and validation.

This is a version-scoped research demonstration. The public project does not establish universal Petrel automation, native marker-pick decoding or creation of arbitrary new Workflow Editor commands. Licensed documentation and demonstration project data are not redistributed.

Review the public README and its honest boundaries.

What this demonstrates

This project connects geoscience software knowledge with agent-tool design: file-based operations first, saved native workflows where supported, bounded UI steps when necessary, and evidence-driven refusal when a route is unproven.
