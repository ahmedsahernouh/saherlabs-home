A practical inventory problem

A project catalogue can contain well, log, seismic and model references without proving that every payload is available or usable. Reviewing a portfolio therefore starts with what can actually be read, which metadata can be linked, and what remains outside the checked scope.

The workflow reads selected project and companion metadata without launching Petrel. It combines registry and Model metadata where readable, records stored CRS declarations, and keeps missing, unsupported or unprobed evidence visible. Read-only database access and bounded file probes support that inventory.

What the result establishes

The recorded local run covered 98 selected project entries: 81 with Registry and Model metadata, four with Registry only, and 13 unavailable. The totals reconcile to the retained verification summary. This public page exposes only those aggregates and the reporting method.

Metadata availability does not establish complete data extraction, correct coordinates, calibrated units or scientific acceptance. A stored CRS declaration needs separate coordinate validation; an object or seismic reference is not proof that its payload was recovered. Unprobed items remain unprobed.

Project identities, source paths, locations, raw records and the original report are excluded from this public example. No runtime or time-saving claim is inferred from recording filenames.
