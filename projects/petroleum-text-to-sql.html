Make the query visible, check it against approved views, then summarize the rows it actually returns.

Explore the sourceFieldViewer AI Lab

A question with a checkable path to the data

The demonstration builds an in-memory SQLite database from compact public Y1-style context files. A question maps to a candidate query using schema context. The SQL validator checks the candidate before execution, and the answer is derived from the returned rows.

The supplied notebook and core module use deterministic generation so reviewers can inspect the workflow without API credentials or paid model calls. They demonstrate the validation boundary for an LLM-assisted workflow; connecting a live model provider remains future work.

Checks before execution

The example validator restricts reads to AI-visible views, rejects write/admin statements and multiple statements, checks hidden-table access, and applies a default row limit. A result-only summary keeps the answer tied to the actual query output.

The standalone schema diagnostic passed on 18 November 2026: declared views and columns, generated query patterns, rejected unsafe examples and a permitted CTE query were consistent. This is a focused demonstration check, not a production security assessment.

The compact demo context is not an operating database. The workflow supports inspectable technical review; it does not validate petroleum interpretations or establish production deployment readiness.
